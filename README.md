# ThingsBrain 企业级物联网平台

ThingsBrain 是一款基于 Dante Cloud 企业级能力构建的物联网平台。它充分继承了 Dante Cloud 国内首个支持阻塞式和响应式服务并行的微服务云原生基座的全部优势，将微服务架构的最佳实践与物联网场景深度融合，为万物互联与 AI 融合提供高可靠、高安全的一站式物联网应用基座。

ThingsBrain 不仅是一套功能完备的物联网平台，更是 Dante Cloud 全栈能力的最佳价值兑现应用场景——通过真实、复杂的物联网业务场景，深度验证了 Dante Cloud 在企业级应用中的架构弹性、安全可靠性与开发效率。

## 一、为什么构建 ThingsBrain

当前，人工智能技术正处于高速发展期，大模型、边缘智能、多模态感知等技术加速成熟，物联网正在从“连接管理”阶段迈向“智能协同”阶段。 与此同时，物联网平台类产品已较为丰富，既有通用型平台，也有面向特定行业的垂直平台。 在AI高速发展、竞品成熟的当下，新建物联网产品岂不是重复造轮子？

之所以在此时推出 ThingsBrain 物联网平台，主要原因是：

### 1. AI 时代并未“消解”软件系统的复杂性，反而放大了架构短板

2026年，AI编程助手已极大提升了单点编码效率，但在平台建设领域，核心瓶颈早已从“代码编写”转移到了“架构治理”。 以物联网为例，设备接入的协议碎片化（MQTT/CoAP/Modbus/私有TCP）、海量并发下的连接状态管理、以及设备影子与业务系统间的数据一致性，这些根本性的分布式系统难题，并未因AI辅助编码而得到丝毫缓解。

### 2. “成熟”竞品与云原生鸿沟

主流的物联网平台产品虽功能齐全，但在技术选型上滞后于云原生浪潮。 它们在响应式编程、虚拟线程（Project Loom）、细粒度服务治理等新一代 Java 技术栈的适配度不足。 这产生以下主要问题：

- **资源利用率低**：传统阻塞式 I/O 模型在处理万级设备长连接时，线程开销巨大，无法充分利用现代云基础设施的算力。
- **扩展性僵化**：缺乏领域驱动（DDD）的模块化拆解，多协议适配、多存储切换等核心能力往往与业务耦合过紧，难以应对企业不同阶段的弹性需求。

### 3. Dante Cloud 构建产品生态的需要

Dante Cloud 作为云原生微服务基座，已在技术底座层面形成较完整的能力积累，涵盖微服务治理、容器化部署、多租户体系、安全认证、服务监控与弹性伸缩等核心能力。 但 Dante Cloud 的目标并不局限于是一套云原生微服务基座，而是向物联网、人工智能方向发展，成为可以支持更多场景、构建完整应用、拥有典型案例产品的软件生态。

## 二、 ThingsBrain 的差异化优势

ThingsBrain 的构建并非重复造轮子，而是基于 Dante Cloud 的技术优势，将 AI 就绪性视为平台的第一性原理

### 1. 生于云原生，而非“被云原生”

ThingsBrain 并非在传统架构上打补丁，而是从第一天起就生长在 Dante Cloud 这一云原生微服务基座之上。 Dante Cloud已深度适配 Spring Boot 4 和 Spring Cloud 2025.1，为AI时代的技术演进预留了友好的底座支持。 这种“原生”优势，不需要大规模重构就可以拥抱云原生。

### 2. 安全基因，生而强大

Dante Cloud 满足国家三级等保要求，支持接口国密数字信封加解密、防刷、高防 XSS 和 SQL 注入等一系列安全体系。 ThingsBrain 继承了这一完整的安全能力，在设备认证、数据传输、权限控制等环节具备天然的安全优势。

### 3. “一套代码、两种架构”的灵活部署能力

ThingsBrain 继承了 Dante Cloud 独特的架构能力——一套代码既可以单体模式运行，也可以微服务模式运行。 这意味着：中小型项目可以低成本快速启动，随着设备规模和业务复杂度增长，可以无缝演进至分布式微服务架构，无需推翻重来。

### 4. 阻塞式与响应式并行，真正的混合运行时架构

Dante Cloud 是国内首个支持阻塞式服务和响应式服务并行的微服务平台。 这一独特的架构能力意味着： ThingsBrain 在处理传统的设备管理、规则引擎等业务时，可以采用成熟的阻塞式编程模型，保证业务逻辑的清晰与可维护性；而在处理海量设备连接、实时数据流处理、推送服务等高并发场景时，则可以无缝切换至响应式编程模型，以极低的资源消耗支撑数万乃至数十万的并发连接。 两种模式并非互斥的二选一，而是在同一平台、同一业务流中按需并存、协同工作。

### 5. 可插拔的多协议、多存储架构

ThingsBrain 具备多协议、多存储可插拔架构，能够灵活适配不同行业、不同场景的物联网需求，避免了“一套方案打天下”的僵化。

### 6. 兼容主流平台，支持物联网平台主流功能

为降低用户迁移门槛、保护既有技术投资，ThingsBrain 在功能设计上主动兼容阿里云物联网平台产品，支持物联网平台领域的主流功能与常见交互模式。 具体包括：

- **设备接入兼容**：支持 MQTT、HTTPS 等主流协议，兼容阿里云物联网平台设备接入认证方式与三元组模型（ProductKey、DeviceName、DeviceSecret），使存量设备可平滑迁移或双平台并行运行。
- **物模型兼容**：支持物模型（Thing Model）定义，兼容阿里云物联网平台物模型规范，包括属性、服务、事件三类核心要素，降低设备侧数据模型转换成本。
- **主流功能全覆盖**：完整支持设备生命周期管理、在线状态监控、设备影子、数据解析、规则引擎、数据转发、告警中心、可视化监控、OTA 升级等物联网平台主流功能

### 7. 与AI融合的天然接口

Dante Cloud 4.X已为AI时代的技术演进预留了底座支持，ThingsBrain在此基础上构建，具备从设备接入、数据采集到AI推理的完整数据链路能力，为万物互联与AI融合提供高可靠、高安全的一站式基座。

## 三、建设目标

ThingsBrain 的建设分为三个阶段：

- **近期目标**： 完成物联网平台核心能力建设，包括多协议设备接入、设备生命周期管理、数据采集与存储、规则引擎、告警中心、可视化监控、开放 API，并完成与 Dante Cloud 的深度集成。同时，实现与阿里云物联网平台在设备接入、物模型、核心 API 层面的基础兼容，形成可运行、可使用的首个生态产品。
- **中期目标**：增强边缘计算与 AI 协同能力，支持边缘节点管理、边缘自治、模型下发、云边数据同步，以及基于规则和模型的智能联动。 进一步深化主流平台兼容能力，完善数据迁移工具和规则转换机制，形成面向重点行业的解决方案模板，积累可复用的场景化能力。
- **远期目标**：使 ThingsBrain 成为 Dante Cloud 生态中成熟稳定的物联网产品，支撑多行业、多客户复制推广，并在此过程中沉淀平台能力，反哺 Dante Cloud 基座，形成“基座支撑产品、产品沉淀能力、能力反哺基座”的生态正循环。同时，保持对主流物联网平台功能的持续跟踪与兼容演进，确保生态产品的长期竞争力。

## 四、核心价值

| 价值维度         | 说明                                                                               |
|------------------|------------------------------------------------------------------------------------|
| **降低开发成本** | 内置设备接入、物模型、设备影子等能力，减少重复造轮子，让团队专注于业务创新。       |
| **缩短上线周期** | 开箱即用，快速搭建物联网业务原型并平滑演进到生产环境。                             |
| **提升系统吞吐** | 响应式架构与统一消息体系结合，支撑海量设备并发连接与消息处理，提升资源利用率。     |
| **增强安全可控** | OAuth2 + MQTT 统一认证，方法级动态鉴权，权限可运营、可审计，满足企业安全合规要求。 |
| **保护既有投资** | 单体到微服务平滑迁移，兼容阿里云物联网平台，降低架构演进和生态切换风险。           |
| **降低运维难度** | 统一消息与认证体系，简化系统集成与日常运维，减少故障排查成本。                     |

```shell
thingsbrain

├    ├── thingsbrain-mqtt-autoconfigure -- Mqtt 业务逻辑自动配置模块
├    ├── thingsbrain-mqtt-commons -- Mqtt 业务逻辑通用代码模块
```

## 八、版本分支

### 1. 版本号说明

本系统版本号，分为四段。

- 第一段、第二段和第三段，与 Spring Boot 版本对应，根据采用的 Spring Boot 版本变更。例如，当前采用 Spring Boot 2.4.6 版本，那么就以
  2.4.6.X 开头
- 第四段，表示在当前 Spring Boot 版本下，系统功能维护及优化情况。

**本系统未采用传统的、从 1.0.0 开始的版本号，主要基于以下两点考虑：一方面，方便了解对应的 Spring Boot 版本；另一方面，与 Dante Cloud 以及 Dante Engine 匹配对应，以减少不必要麻烦。**

### 2. 分支说明

| 分支名称 | 对应 Spring 生态版本                     | 对应 JDK 版本 | 用途             | 现状                                                         |
|:--------:|------------------------------------------|---------------|------------------|--------------------------------------------------------------|
|  master  | Spring Boot 4.1 和 Spring Cloud 2025.1.3 | JDK 25        | 主要发布分支     | 推荐使用代码分支                                             |
| develop  | Spring Boot 4.1 和 Spring Cloud 2025.1.3 | JDK 25        | Development 分支 | 新功能、ISSUE 均以此分支作为开发，发布后会 PR 至 master 分支 |
